# Security Policy

## Supported versions

The project is pre-release. Security fixes are provided only for the latest revision of the
default branch until the first stable release.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability
reporting feature under the repository **Security** tab.

Include the affected revision, impact, reproduction conditions, and any suggested mitigation.
Do not include real secrets, personal data, or harmful payloads beyond what is necessary to
understand the report.

Maintainers aim to acknowledge reports within three business days and provide an initial
assessment within seven business days. Timelines may vary with severity and complexity.

## Scope

Reports may cover source code, CI/CD, dependencies, model artifacts, data supply chain, serving
behavior, or ways the classifier could create a false sense of security. Adversarial prompts that
only demonstrate expected model limitations may be redirected to the public evaluation process.
